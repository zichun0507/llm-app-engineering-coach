# 基础层：Transformer、上下文成本与幻觉

> 什么时候读这个文件：用户问注意力机制、上下文长度、KV Cache、幻觉成因，或"为什么长上下文又贵又不准"。

---

## 1. 一句话本质

**让句子里的每个词，先环顾四周看看别人在说什么，再决定自己是什么意思。**

传统词向量给同一个词永远同一个向量，两个"银行"没法区分。注意力机制让每个词对所有词算一遍相关度，再加权融合上下文。

---

## 2. 五个模块

| 模块 | 作用 | 一句话比喻 |
|---|---|---|
| Tokenizer + Embedding | 文本 → 向量 | 给每个词发一张数字身份证 |
| Positional Encoding | 注入顺序 | 给每个人发座位号，否则"我打你"等于"你打我" |
| Self-Attention（多头） | 融合上下文 | 同时开 8 个小组会：语法组、指代组、情感组 |
| FFN + 残差 + Norm | 非线性表达 + 训练稳定 | 会后各自独立思考，再和原话对账 |
| 输出头 | 生成概率 | 决定吐标签、吐向量，还是吐下一个词 |

位置编码的四代：正弦（原版）→ 可学习（BERT）→ **RoPE（当前主流：Llama/Qwen/DeepSeek）** → ALiBi（长文本外推方便）。

---

## 3. 注意力公式与直觉

```
Attention(Q,K,V) = softmax(QKᵀ / √d_k) · V
```

- **Q** = 我要找什么；**K** = 我能提供什么标签；**V** = 我真正的内容
- 图书馆比喻：Q 是检索词，K 是书脊标签，V 是正文
- **除以 √d_k 的原因**：维度一高，点积方差就大，softmax 会饱和成 one-hot，梯度直接死。除根号是为了把方差拉回 1

**多头**：把 d_model 切成 h 份各算各的，不同头会自发分工（指代、句法、位置）。**MQA / GQA** 让多个 Q 共享 K、V，代价是少量精度，收益是 KV Cache 大幅缩小。

## 4. 长上下文的四本账

这是本节最值钱的部分。用户问"为什么上下文越长越贵"，必须四本账一起给。

### 账本 1｜算力：二次方

```
Attention FLOPs ≈ 4 · L · n² · d
```

n 是序列长度，平方项。上下文翻倍 → 这部分算力翻 4 倍；翻 10 倍 → 翻 100 倍。
FFN 只是 `O(n·d²)` 线性增长，所以**短上下文时 FFN 是大头，长上下文时注意力反超**。

体感：首字延迟（TTFT）从 0.5 秒变成 20 秒以上。

### 账本 2｜显存：KV Cache

```
KV Cache = 2 · L · n · h_kv · d_head · bytes
```

Llama-3-8B（32 层、8 个 KV 头、head_dim 128、BF16）：

| 上下文 | KV Cache | 说明 |
|---|---|---|
| 4K | 0.5 GB | 轻松 |
| 32K | 4 GB | 24G 卡还行 |
| 128K | 16 GB | 单卡基本吃光 |
| 1M | 128 GB | 必须多卡或用 MLA 压缩 |

一张 80G 卡，权重占 16G，剩下全给 KV Cache，**并发数直接归零**。长上下文不是"能不能算"，是"一张卡能服务几个人"。

### 账本 3｜延迟：带宽瓶颈

解码每吐一个 token，都要把整个 KV Cache 从显存读一遍。这是 memory-bound，算力单元大量闲置。**上下文越长，每 token 生成越慢**，用户体验是"越吐越慢"。

### 账本 4｜效果：最容易被忽略

- **注意力稀释**：softmax 要在 n 个位置分配总和为 1 的权重，n 越大每个位置分到的越少，信噪比下降
- **Lost in the Middle**：开头和结尾召回率高，中间明显掉 → 关键指令放头尾
- **多跳推理衰减**：单点"大海捞针"能过，但"A 文档的日期 + B 文档的条件"组合推理掉得很快
- **位置编码外推**：标称 128K，有效区间常只有 50%–70%

**结论**：**长上下文是应急手段，不是默认方案。** 能用检索捞 5 个片段解决，就别塞 20 万字——更便宜、更准、更可更新。

## 5. 幻觉的五层根因

先纠正误解：**幻觉不是 bug，是架构的默认行为。**

训练目标是"给定前文，最大化下一个 token 的似然"——**它的本职是"续写得像人话"，不是"说得对"**。不知道的时候，最优策略不是沉默，而是生成统计上最像答案的东西。

| 层级 | 根因 | 表现 | 可治性 |
|---|---|---|---|
| ① 模型本质 | 参数是语料的有损压缩，没有数据库、没有指针 | 长尾实体张冠李戴，编造论文/法条/API | 不可根治，只能外挂知识 |
| ② 解码策略 | 采样有随机性 | 同问题两次答案不同 | 可缓解（降温度、约束解码） |
| ③ 知识时效 | 参数有 cutoff，无版本无溯源 | "最新政策是……"其实是两年前的 | 用检索解决 |
| ④ 上下文质量 | 检索召回错/过期/被污染 | **有据可依地胡说，还带引用** | 检索与清洗能治 |
| ⑤ 对齐副作用 | RLHF 奖励自信、惩罚"我不知道" | 越不确定越信誓旦旦 | Prompt + 训练 + 产品设计 |

**④ 是企业 RAG 里最高发的一种**，业内叫"垃圾进、自信出"。所以**别一有幻觉就换更大的模型，先看检索**。

---

## 6. 幻觉的分型治理

| 类型 | 场景 | 对症手段 |
|---|---|---|
| 事实性幻觉 | 编造实体/数字/日期 | 强制检索 + 句级引用 + 无据不答 |
| 忠实性幻觉 | 有资料但答歪 | 限定只用给定材料 + 抽取式优先 + 引用校验 |
| 推理幻觉 | 算错、逻辑跳跃 | 先列步骤再结论，或用工具/代码算 |
| 格式幻觉 | JSON 缺字段、瞎编枚举 | Schema 约束 + 解析失败自动重试修复 |
| 越界幻觉 | 超出能力硬答 | 拒答样本 + 明确兜底话术 |

**最重要的一条产品原则**：**给模型一条体面的退路。**

Prompt 里必须写"资料中没有相关信息时，直接回答『根据现有资料无法确定』，不要推测"。模型的默认压力是"必须给个答案"，你得主动把它解开——这一句能把幻觉率砍掉一大截。

---

## 7. 常被问到的三个延伸

**Q：既然有长上下文，为什么还要 RAG？**
成本（KV Cache 与 prefill 二次方）、精度（信噪比）、可更新性（改文档不用重发全量）。RAG 是常态，长上下文是特例。

**Q：为什么长上下文会"忘记"前面的内容？**
不是遗忘，是注意力被稀释 + 位置外推失效。信息还在上下文里，只是权重分配不过来。

**Q：幻觉能彻底解决吗？**
不能。只能把"不可控的编造"变成"可控的可查证"。工程目标是**降低到业务可接受**，不是归零。
